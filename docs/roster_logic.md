# SimBaseBall-game 選手起用ロスター管理ロジック仕様書

## 1. 概要
本ドキュメントでは、チームの戦力管理の中核となる「一軍二軍入れ替えロジック」および「スターティングメンバー決定ロジック」の仕様を記述します。

## 2. 一軍二軍入れ替えロジック
**ファイル**: src/services/rosterManager.ts

### 2.1. 基本ルール
*   **一軍登録枠**: 最大29人
*   **外国人枠**: 最大5人 (一軍登録)
*   **ポジション別目安**: 投手13人, 捕手3人, 内野手7人, 外野手6人
*   **10日間ルール**: 抹消された選手は10日間再登録不可（怪我や特例を除く）

### 2.2. 入れ替え判定フロー
日次シミュレーション前に processDailyMoves メソッドで実行されます。

1.  **自動抹消**:
    *   injuryStatus が healthy でない選手は即座に二軍へ降格。

2.  **強制降格 (人数超過時)**:
    *   一軍枠(29人)を超えている場合、目標人数目安を超過しているポジションから候補を選出。
    *   **評価スコア**が最も低い選手を強制的に降格。

3.  **昇格入れ替え検討**:
    *   二軍選手を評価スコア順にソートし、上位から検討。
    *   **条件**:
        *   10日間ルールに抵触しない。
        *   怪我をしていない。
        *   **評価比較**: 候補スコア > 最低評価一軍選手スコア + 閾値(10)
    *   条件を満たせば入れ替え実行。

### 2.3. 評価スコア計算 (`evaluatePlayer`)
選手を比較するための数値指標です。

*   **基礎点**: `abilities.overall` (なければ能力平均値)
*   **成績補正**:
    *   投手 (防御率): `(3.50 - ERA) * 15`
    *   野手 (OPS): `(OPS - 0.650) * 200`
    *   *5試合以上出場時のみ適用*
*   **疲労ペナルティ**: 投手の疲労度 > 20 の場合、その分マイナス。

###  残存課題

| 課題 | 現状の挙動 | 修正案 |
| :--- | :--- | :--- |
| **成績の影響度** | シーズン序盤(5試合未満)は能力値のみで固定され、調子の良い若手が上がってこない。 | 直近5試合の成績や、二軍成績の概念を導入するか、ランダムな「調子」ボーナスを加える。 |
| **閾値の固定** | 常に THRESHOLD = 10 で固定。 | チーム事情（連敗中など）に応じて閾値を下げ、入れ替えを活性化させる。 |
| **ポジションバランス** | 目安人数を厳守しすぎる。 | 打撃専門の選手（守備下手）が「内野手過多」などの理由で落とされやすい。DH要員としての評価を加味する。 |

## 3. スターティングメンバー決定ロジック
**ファイル**: src/services/databaseManager.ts

### 3.1. 先発投手選出 (getStartingLineup)
1.  **候補フィルター**: 先発適性(3以上) かつ スタミナ(8以上)。
2.  **疲労チェック**: 疲労度 < 5 の選手のみ。
3.  **優先度**:
    1.  疲労度が低い順
    2.  先発適性が高い順
    3.  総合ステータスが高い順

### 3.2. 野手スタメン選出 (selectBestStarters)
各守備位置（C, 1B, 2B...）ごとにベストな選手を割り当てていきます。

*   **スコア計算式**:
    ```typescript
    Score = (適性 * 2) + 守備力 + (肩 * 0.5) - (適性不足ペナルティ) + (打撃スコア * 0.6)
    ```
    *   **打撃スコア**: `(Contact * 1.5 + Power + Eye * 0.5) + ランダム(0-15)`
    *   *以前は係数が0.15だったが、0.6に引き上げられ打撃重視の傾向が強まった。*

*   **フロー**:
    1.  守備位置ごとに候補者をリストアップ。
    2.  上記スコアでソートし、1位をそのポジションに固定。
    3.  残った選手の中からDHを選出（純粋な打撃スコア順）。

### 3.3. 打順決定 (`optimizeBattingOrder`)
選出された9人に対し、打順ごとの適性スコア（Excel由来）を計算し、グリーディ法（1番から順に最善を埋める）で決定。

*   **評価基準**:
    *   1番: 巧打・選球・走力
    *   2番: 巧打・選球・走力・バント
    *   3番: 巧打・長打・選球
    *   4番: 長打・巧打 (最重要)
    *   ...

###  残存課題

| 課題 | 現状の挙動 | 修正案 |
| :--- | :--- | :--- |
| **DH選出の順序** | 守備位置を8つ全て埋めた「余り」からDHを選ぶため、**「守備は下手だが最強の打者」がDHに選ばれず、スタメン落ちする**可能性がある。 | 本来は「全選手から最強打者を数名ピックアップ→守備位置 or DHに割り当て」とすべき。 |
| **適性重視厳密** | 適性が `3` 未満だとペナルティが大きい `(3 - aptitude) * 5`。 | コンバートやサブポジ持ちが使いにくい。ペナルティを少し緩和する。 |
